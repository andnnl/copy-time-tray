# JSON 菜单与格式化窗口设计

**日期：** 2026-07-11

## 目标

在系统托盘菜单中提供“JSON”入口，打开一个双栏格式化窗口。用户既可手动粘贴或编辑 JSON，也可从剪贴板读取 JSON；选择格式后生成结果，并可复制结果回系统剪贴板。默认格式为 **4 空格美化**。

## 范围

本次仅实现 JSON 文本的解析与格式化，不包含 JSON Schema 校验、JSON 与 YAML/XML 转换、文件读写、历史记录或格式偏好持久化。

## 用户界面与交互

窗口采用已确认的双栏布局：

- 左栏“输入 JSON”：可编辑多行文本框。
- 右栏“格式化结果”：只读多行文本框；格式化成功后展示结果。
- 格式方式选择器位于输入与结果区域上方，默认选中“4 空格美化”。
- 操作按钮：
  - “从剪贴板粘贴”：读取纯文本剪贴板内容并覆盖左栏输入，不立即格式化。
  - “格式化”：按当前格式方式解析左栏内容并更新右栏结果。
  - “复制结果”：将右栏结果写入系统剪贴板；没有结果时不执行复制。
  - “关闭”：关闭窗口而不修改剪贴板。

托盘菜单新增顶级“JSON”菜单项，点击后打开该窗口。原有时间、密码、MD5、配置、代码片段、同步和退出菜单功能保持不变。

## 格式方式

选择器包含以下四项：

| 显示名称 | 输出规则 |
| --- | --- |
| 4 空格美化（默认） | 解析 JSON 后，以每级 4 个空格缩进序列化，结尾不额外添加换行。 |
| 2 空格美化 | 解析 JSON 后，以每级 2 个空格缩进序列化，结尾不额外添加换行。 |
| 压缩单行 | 解析 JSON 后输出紧凑单行 JSON。 |
| 转义为 JSON 字符串 | 解析 JSON 以验证输入合法；随后把原始输入文本编码为一个 JSON 字符串字面量。 |

所有格式都必须先解析输入，因此无效 JSON 不产生结果，也不会覆盖剪贴板。

## 数据流与错误处理

1. 用户手动输入文本或点击“从剪贴板粘贴”。
2. 用户选择格式方式并点击“格式化”。
3. 格式化逻辑使用 `serde_json` 验证输入；美化和压缩方式按已解析的 JSON 值重新序列化。
4. 成功时更新右栏文本并启用“复制结果”。
5. 解析失败时保留左栏输入与上一份成功结果，展示包含 `serde_json` 错误信息的可见错误提示；不写剪贴板。
6. 用户点击“复制结果”后，将右栏当前结果写入系统剪贴板，并显示成功反馈。

## 架构

- 抽取不依赖 GUI 的 JSON 格式化模块，定义格式枚举和接受 `&str`、返回 `Result<String, serde_json::Error>` 的格式化函数。该模块用单元测试覆盖四种输出和非法 JSON。
- Linux 继续使用现有 GTK 栈：新增 GTK 对话框函数，通过现有托盘菜单回调调用；GTK 自身负责剪贴板读取和写入。
- Windows 使用已有 `eframe`/`egui` 依赖启动独立原生窗口，并通过 `arboard` 与剪贴板交互。托盘事件循环在启动该窗口时保持可用，防止菜单事件被阻塞。
- 两个平台都共享同一格式化模块与格式名称，保证格式化结果一致。

## 验收标准

1. Linux 和 Windows 的托盘菜单均显示“JSON”入口。
2. 打开窗口后默认选中“4 空格美化”。
3. 用户可手动输入合法 JSON，分别得到 4 空格、2 空格、压缩单行及 JSON 字符串转义结果。
4. 用户可把剪贴板文本载入输入区；格式化后的结果可复制到剪贴板。
5. 非法 JSON 显示错误，输入和最后一次成功结果保持不变，且不覆盖剪贴板。
6. JSON 格式化模块的单元测试覆盖成功输出及非法输入；项目构建和全量测试均通过。
