# 收藏片段标签栏与云同步设计

## 背景与目标

为代码片段增加跨设备一致的收藏状态，并在搜索框下方展示已收藏片段。标签栏采用用户确认的 B 方案：接近浏览器标签页的横向结构；所有按钮、图标、圆角、背景和交互状态沿用当前窗口已有的视觉风格。

GitHub 文件格式增加稳定片段 ID 与持久化的远端文件路径，以确保片段重命名后仍被识别为同一项。

## 范围

### 纳入范围

- 普通代码片段的收藏、取消收藏与收藏栏展示。
- 搜索结果、主列表和收藏标签中的右键收藏操作。
- 收藏操作复用本地更新、刷新与自动同步调度链路。
- Gitee tree.json 与 GitHub 单片段 YAML 读写 `favorite` 和稳定 `id`。
- 新旧本地数据、旧 Gitee tree.json 和旧 GitHub YAML 的兼容读取。
- 单元测试覆盖收藏状态、序列化、同步格式、合并与重命名身份匹配。

### 不纳入范围

- 文件夹收藏。
- 改变现有主列表、搜索结果的排序规则。
- 为标签增加独立关闭按钮、拖拽排序或固定顺序配置。
- 改造现有同步协议以外的第三方导入导出格式；Termora 导入的片段默认未收藏。

## 数据模型与本地存储

`Snippet` 增加 `favorite: bool` 字段，并使用 `#[serde(default)]`。这使缺失字段的历史 `snippets.json`、Gitee tree.json 以及 GitHub YAML 都以 `false` 反序列化。

- `Snippet::new_snippet` 和 `Snippet::new_folder` 均初始化为 `favorite: false`。
- 仅 `SnippetType::Snippet` 可以切换收藏状态；文件夹始终不显示收藏入口。
- 收藏切换通过 `SnippetStore::update` 完成，因而自动更新时间戳、设为 `synced: false`、持久化本地文件，并由调用方触发既有 debounce 自动同步。
- 收藏栏按 `update_date` 降序展示。由于切换收藏会更新时间戳，最近收藏的项目排在前；取消收藏后立即从栏中移除。

## 同步协议

### Gitee

Gitee 的单 Gist tree.json 当前已保存片段 ID、名称、内容、类型、删除标记和时间戳。`TreeEntry` 增加 `favorite`，构造 tree 时写入，解析远端 tree 时恢复。旧 tree.json 缺少该字段时按未收藏处理。

Gitee 是整棵树同步：推送完整树并保留既有的删除墓碑策略；拉取仍按本地 `Snippet.id` 对应，并按 `update_date` 采用最后更新时间优先（LWW）合并。因此收藏状态自然随胜出的完整记录同步。

### GitHub

GitHub 的每个普通片段对应 `snippets/<sanitize(name)>.yaml`。为确保沿用名称文件格式的旧仓库在重命名时仍可精确更新，`Snippet` 另增本地持久化字段 `github_remote_path: Option<String>`（`#[serde(default)]`）。该字段记录最后一次拉取或成功推送所使用的远端路径；它不是 Gitee tree.json 的业务字段。YAML 的远端 DTO 增加：

```yaml
id: "稳定 UUID"
favorite: true
```

- `snippet_to_yaml` 始终写入本地 `Snippet.id` 与 `favorite`。
- `parse_yaml_snippet` 优先使用 YAML 中的 `id`；当旧 YAML 没有 `id` 时，才沿用当前基于相对路径生成的兼容 ID，并将该路径写入 `github_remote_path`。
- 新建片段的目标路径仍由当前名称生成；成功推送后，记录该路径到 `github_remote_path`。重命名时，推送逻辑以 `github_remote_path` 识别旧文件：先在新名称路径写入带同一稳定 ID 的 YAML，确认成功后删除旧路径，最后将本地路径更新为新路径。这样不会因名称变化而重复创建本地记录或丢失收藏状态；失败时旧路径保留，本地项目仍标记待同步，供下次同步重试。
- 拉取后的 `load_from_sync` 按 YAML 的稳定 ID 合并。一个拉取批次出现同一稳定 ID 的多个文件时，仅保留 `update_date` 更新的记录，以容忍重命名写入成功但旧路径删除尚未完成的短暂状态。
- 保持现有 GitHub 待同步增量推送策略与失败重试/通知行为。

所有平台继续按片段级 `update_date` 处理冲突：两个设备都修改同一片段时，时间较新的完整记录覆盖较旧记录；收藏与取消收藏均属于对该片段的修改。

## UI 与交互

### 收藏标签栏

搜索框正下方仅在存在至少一个未删除、类型为普通片段且 `favorite == true` 的项目时显示收藏栏。

- 使用横向、可换行的浏览器标签式布局，窄窗口下标签自动折行，不裁剪项目。
- 单个标签显示与当前界面一致的星标图标和片段名称；名称过长按当前 UI 的可用宽度截断或裁剪。
- 标签复用当前窗口按钮的圆角、边框、背景、文字色、悬停和按压样式；不引入独立设计语言。
- 左键点击标签：复制片段内容，沿用已有剪贴板与复制反馈流程。
- 右键点击标签：打开现有风格的上下文菜单，仅提供「取消收藏」。执行后即时刷新标签栏和搜索结果。
- 标签不提供关闭按钮；取消收藏只通过右键菜单，避免产生与当前按钮系统不一致的控件。

### 收藏入口

普通片段在以下位置右键均出现「收藏」或「取消收藏」：

1. 搜索结果。
2. Linux 主列表中的片段行。
3. 收藏标签。

文件夹不显示该菜单项。现有编辑、删除、复制和文件夹导航行为保持不变。

### 状态更新

UI 以 `UiResponse` 增加专用的收藏切换消息（携带片段 ID 和目标状态），由应用层调用 `SnippetStore::update`。更新成功后：

1. 立即刷新当前可见 UI；Windows 向搜索窗口发送完整刷新快照。
2. 调用 `SnippetManager::schedule_push()`，交由现有配置开关、5 秒 debounce、拉取合并、推送和通知逻辑处理。
3. 若同步失败，收藏状态仍保留在本地，等待现有重试或下次手动同步。

## 错误处理与兼容性

- 找不到片段 ID 时，收藏切换返回既有 `StoreError::NotFound`；UI 不改变本地显示状态。
- 文件夹或已删除项的收藏切换在 UI 层阻止；存储层接口也应避免把文件夹作为可收藏对象。
- 旧客户端可读取 GitHub 新 YAML 中新增的字段，若其忽略未知字段则不会展示收藏；其重命名行为仍受既有按文件名身份识别的限制。新客户端可读取旧格式，并将在下次推送时补齐稳定 ID 和收藏字段。
- 旧 GitHub YAML 在首次被新客户端读取时以路径派生 ID 兼容，并记录该路径；之后一次成功推送会在原路径补齐稳定 ID 和收藏字段。重命名后的后续同步据此路径迁移文件。对于此前已同名路径的记录，保持现有冲突规则，不额外引入迁移向导。

## 测试策略

1. **模型与存储：** 新建片段默认未收藏；缺失 `favorite` 的 JSON 反序列化为 `false`；收藏切换持久化、更新时间并设为待同步；文件夹不可收藏。
2. **Gitee 同步：** tree.json 写入和读取 `favorite`；缺失字段默认未收藏；远端较新的收藏状态按 LWW 覆盖本地。
3. **GitHub 同步：** YAML 输出稳定 `id` 与 `favorite`；新 YAML 解析保持 ID、收藏状态与远端路径；旧 YAML 缺失字段时使用路径派生 ID、默认未收藏；重命名时先写新路径再删除记录的旧路径，并用稳定 ID 合并为同一个本地片段；拉取到重复稳定 ID 时保留较新的记录。
4. **UI 纯逻辑：** 收藏栏过滤条件排除删除项和文件夹，按更新时间降序；标签点击使用现有复制响应；右键目标状态为收藏或取消收藏。将可测试的筛选和菜单判定提取为无 GUI 依赖的函数。
5. **回归验证：** 运行 `cargo test`，并运行 `cargo build` 确认 Linux 默认目标可编译；若环境具备 Windows GNU target，再运行 `cargo check --target x86_64-pc-windows-gnu` 验证 Windows `egui` 路径。

## 验收标准

- 用户可在任一代码片段入口收藏或取消收藏，文件夹没有收藏操作。
- 收藏片段出现在搜索框下方的 B 式标签栏；点击可复制，右键可取消收藏，且视觉风格与现有按钮一致。
- 收藏状态写入本地，触发现有自动同步，并可通过 GitHub 或 Gitee 在其他设备上恢复。
- GitHub 重命名后的 YAML 仍通过稳定 ID 与原片段合并，收藏状态不丢失、不重复。
- 缺少新字段的本地和云端旧数据可正常打开，默认未收藏。
- 全量测试和构建命令成功完成。
