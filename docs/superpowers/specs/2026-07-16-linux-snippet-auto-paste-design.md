# Linux 代码片段复制后自动粘贴设计

## 目标

在 X11 会话中，用户从代码片段管理器复制一个非空片段后，窗口自动隐藏，并将内容粘贴到打开代码片段窗口前处于活动状态的外部输入窗口（例如终端或 Shell 工具）。

## 范围与约束

- 仅修改 Linux GTK 代码片段管理器；Windows 和托盘中其它复制功能不变。
- 目标窗口在显示片段窗口前通过 `xdotool getactivewindow` 记录。
- 复制后必须先隐藏管理器窗口，避免 `Ctrl+V` 被发送到自身。
- 使用 `xdotool windowactivate --sync <window-id>` 恢复此前窗口，再执行 `xdotool key --clearmodifiers ctrl+v`。
- 无法获取目标窗口、`xdotool` 不存在或任何命令失败时，静默降级为“内容已复制到剪贴板”：不展示错误、不取消复制、不尝试向未知窗口发送按键。
- 双击片段与“复制”按钮共用同一个复制、隐藏和自动粘贴流程。

## 方案比较

1. 在 GTK/GDK 内部直接恢复焦点并合成键盘事件：无需外部依赖，但需要 X11 专用低层绑定，当前依赖中没有稳定接口，改动与测试成本较高。
2. 使用已安装的 `xdotool`：可精确地读取、激活 X11 窗口并发送按键；与当前系统环境匹配，命令调用可通过纯函数测试隔离。选择该方案。
3. 仅依赖剪贴板选择所有权：无法满足“直接粘贴”，不采用。

## 架构与数据流

`linux_manager::show` 在构建 GTK 对话框前调用 `capture_active_window`。该函数执行 `xdotool getactivewindow`，解析正整数窗口 ID，并在失败时返回 `None`。该 ID 被复制进双击和“复制”回调。

两个回调调用 `copy_and_paste_snippet`：它先将片段写入 GTK 剪贴板，再隐藏主对话框并释放单窗口标记，最后若存在窗口 ID，调用 `paste_into_window`。后者依次激活目标窗口与发送 `Ctrl+V`；任何阶段失败即返回，不影响已完成的剪贴板复制。

## 测试

纯逻辑单元测试覆盖：窗口 ID 解析拒绝空值、非数字、零与多余输出；命令构造使用预期的 `windowactivate --sync` 和 `key --clearmodifiers ctrl+v` 参数；复制流程的计划要求先隐藏再执行粘贴。GTK/真实 X11 自动化不纳入单元测试，最终以在 X11 下编译、全量测试和发布构建验证。
